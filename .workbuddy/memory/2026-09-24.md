# 2026-09-24 工作日志

## 任务：菜谱推荐器安全架构改造

### 问题背景
用户发现 Cloud Service 的 publishable key 暴露在 HTML 文件中，存在安全风险——任何人拿到 key 都可以直接调用 LLM API 消耗积分。

### 解决方案
采用前后端分离架构，key 只存在于服务器端：

```
浏览器 → /api/chat (代理) → Node.js 持有 key → Cloud Service LLM API
         (无 key)                (转发请求，返回结果)
```

### 实现细节

1. **创建 server.js** (Node.js 代理服务器)
   - 端口 3000，提供静态文件服务和 API 代理
   - API Key 只在服务端持有
   - 请求频率限制（单 IP 每分钟最多 10 次）
   - 输入参数校验（防止注入）
   - 响应体大小限制（防大体积消耗积分）
   - 强制 stream: true（Cloud Service LLM API 要求）

2. **更新 recipe-recommender.html**
   - 移除暴露的 ACCESS_KEY 变量
   - 改为调用 `/api` 代理路径
   - 去掉动态获取模型列表逻辑（固定使用 auto 模型）
   - 简化初始化流程

### 安全措施清单
- ✅ Key 不暴露给前端

- ✅ 输入校验防注入
- ✅ 大小限制防滥用
- ✅ CORS 支持
